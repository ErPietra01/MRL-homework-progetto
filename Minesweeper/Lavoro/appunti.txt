della coppia vettore delle features - azione; tuple di features nuove hanno inizialmente valore 0 di default;

in ogni iterazione: devo:
- fare un check di tutti gli stati ammissibili;
- calcolare la chiave (features-azione) per ciascuno stato ammissibile e per ciascuna azione;
- scegliere la chiave col valore maggiore secondo una logica greedy.

A ogni turno:
    - calcolo le features per ogni cella candidata
    - scelgo con epsilon greedy la cella da scoprire confrontando i valori delle features s in Q
    - invio tramite step le coordinate della cella scelta all'ambiente
    - l'ambiente restituisce una reward e lo stato successivo
    - ricalcolo le features s' per le celle candidate nel nuovo stato
    - aggiorno il valore della tupla di features s scelte
    - passo allo stato successivo 

azione = quale cella rivelare


ISTRUZIONI PER L'AMBIENTE E PER LE FUNZIONI AUSILIARIE

MinesweeperEnv: chiamato una volta sola all'inizio del programma per creare la griglia
reset(): nessun argomento o return; serve a ottenere una nuova disposizione delle mine all'inizio di ciascun
episodio
env.step(action_index): prende l'indice della cella e restituisce la reward e se l'episodio è finito
env.state: lista di dizionari che assegna un valore a ciascuna casella (1-8 + B + H + U)
TUTTI GLI ALTRI NON VANNO TOCCATI

get_hidden_cells(env): da usare una sola volta prima della selezione dello stato. Permette
di ottenere una lista aggiornata delle caselle ancora nascoste
build_coord_lookup(env): via di mezzo tra Q e le coordinate; calcola il valore di ciascuna cella
get_cell_neighbors_values: presa una coordinata, restituisce la lista dei valori dei vicini
get_features: da usare per ogni cella candidata; restituisce la tupla delle features
features_to_key: restituisce la tupla come chiave di Q
detect_actually_revealed: seve solo nel controllo iniziale 

azione greedy: scelgo la cella relativa al valore più alto delle features, oppure una 
cella a caso tra quelle disponibili (ma solo dopo la prima mossa casuale)
